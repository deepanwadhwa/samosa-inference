# Concrete backend recipe compatibility

`package_backend_compatible` is a trusted publication validator. Unknown recipes
refuse `unsupported_package_recipe`; a callback's existence is not substituted
for a concrete backend policy. Its context supplies the host-owned absolute
payload path and bounded control hook. Public requests cannot select callbacks,
paths or compatibility policy.

Current recipe: `sherpa-speech-package-v1`. The generic index must contain the
native `manifest.json` as a metadata payload. Its pinned digest supplies the
existing complete speech verifier and loader inspector. The validator first
obtains a verified native package receipt, then reuses the transitive graph check
with native host policy and before/after package observations. Architecture/OS,
ABI declaration, dependency closure/versions, native data/reference files and
unsafe loader environments retain their existing strict rules.

No library/model is loaded by this inspection. Actual loaded ABI, successful model
requests and readiness remain lifecycle/qualification gates. Generic tree hashes
and complete-index checks still run around this callback in publication. Native
speech manifest roles remain authoritative for model/runtime configuration.
Other backend recipes, acquisition coordination, recovery and public installation
remain unfinished; unknown recipes are never accepted as compatible.
