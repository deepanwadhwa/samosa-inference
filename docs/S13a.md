# S13a — verified provider artifacts and readiness

Named next task after S12b, contributing to C03/C04. Owner: Inference.
No Python, sibling private code/state, model requirement for Sources or App, or
provider-specific branching in Agent/App. This task does not close C03/C04 alone.

Implement a native bounded streaming artifact manager and generic public
installation/readiness descriptors. Host configuration supplies artifact ID,
expected SHA-256, exact size, private install directory and acquisition source;
public requests cannot choose paths, executable commands or URLs. An artifact
identity binds checksum and size. Maximum 16 configured artifacts, one active
installation, fixed 64KiB working buffer and explicit host byte/disk ceiling.
Configured model weights remain optional. Model-free builds retain no curl link.

Installation stages bytes in owner-private state, resumes only the same pinned
artifact after proving the previous worker dead, verifies full streamed checksum
and exact length, fsyncs, and publishes without replacing foreign content.
Partial, truncated, corrupt, oversized or interrupted artifacts never report
ready. Existing verified artifacts survive failed acquisition/activation of a
different version. Retries and worker death never silently activate a provider.
Symlink/nonregular inputs and replaced state roots refuse. In-place mutation of
retained files invalidates verification; verification cannot rely on mtime alone.

Generic descriptors distinguish absent, installing, interrupted, invalid,
verified and ready; verified bytes do not imply a running compatible engine.
Readiness additionally validates the configured adapter's public alias/context
and explicit engine identity qualification. External engines without an owned
artifact relationship report that limitation, never checksum-qualified readiness.
Acquisition and activation are separate operations. Ownership of an engine
process requires its own launch lease and process-group lifecycle; no stopping
personal or merely discovered engine processes.

Acceptance before implementation is declared complete:

1. Standard SHA-256 vectors and streamed multi-block/large fixtures; fixed memory
   usage independent of artifact length; declared size and byte ceilings enforced.
2. Small fake artifact install, interrupted worker, explicit resume, exact retry,
   corrupt/truncated/oversized input and wrong checksum; no ready publication.
3. Concurrent install refusal, foreign file/symlink/state-root replacement,
   source mutation and publication crash recovery with no destructive replay.
4. Failed new-version activation preserves last-good provider; missing/changed
   public alias/context and unqualified external engine produce distinct status.
5. Plain Sources and model-free Inference build/test with provider absent.
6. Independently copied macOS ARM64 and native Debian12 ARM64 regular/sanitizer/
   release tests plus package-content verification. Actual supported provider
   checks remain separate from controlled HTTP fixtures.

Record exact implemented scope, commands, counts, failures and limits in the
architecture verification checkpoint. Remote acquisition, residency, end-to-end
cancellation and assembled product qualification remain required follow-on work
unless independently implemented and qualified here.

Engine ownership continuation design (recorded before engine implementation):
use a foreground Inference supervisor started by App or an explicit headless host.
Only configured verified engine/model artifact descriptors may be activated.
Hold verified inputs and revalidate their relationship at launch; metadata alias
alone is insufficient. Own process groups and a lifecycle lease, bound startup/
shutdown/log sizes and clean up only directly owned children after parent death.
Activation is an explicit operation, separate from import. Keep the last-good
activation configuration durable and unchanged until a candidate qualifies;
failed candidates leave that configuration recoverable. Respect the single large
model residency policy during switching rather than overlapping old/new engines.
Required fixtures: exec/startup/readiness failure, replacement of either input,
failed new version with last-good recovery, parent/engine SIGKILL and foreign
engine isolation. Actual native provider launch/verified inputs is a separate gate
from controlled fixture metadata checks.

Lifecycle primitive now implemented in engine_process.c/h: trusted configured
argv<=32/16KiB, absolute executable, hidden self guardian with a private pipe
lifeline, child process-group ownership, reserved leader until cleanup, bounded
2-second start handshake and up to24-hour configured engine lifetime. Guardian
drains/discards logs with a1MiB maximum processed-byte limit (no retained log
file), kills only its directly owned group on deadline/log limit/parent death/
explicit stop or leader exit. Stop observes bounded2-second response plus
bounded2-second reap; a stalled guardian returns shutdown_pending and retains
its handle for later observation. Blocking host syscalls retain host limitations.
This primitive alone grants no activation/readiness or artifact identity. Direct
SIGKILL of the guardian itself is not yet a qualified cleanup case; do not infer
all-helper-crash resilience from the owning-parent SIGKILL checks.

Dependency closure continuation: qualify a pinned native llama-server package
with BUILD_SHARED_LIBS=OFF, LLAMA_OPENSSL=OFF, GGML_BACKEND_DL=OFF and embedded
Metal library on macOS. Keep its build outside personal backend state. Inspect
the pinned executable's direct loader dependencies under system-runtime-v1;
reject external/rpath backend libraries and loader/plugin environment overrides.
OS runtime is a declared platform dependency, not included in the engine digest.
Package provenance and actual launch qualify engine-specific late-loaded assets;
generic binary inspection alone cannot prove the absence of arbitrary dlopen.
