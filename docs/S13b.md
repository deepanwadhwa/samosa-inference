# S13b — trusted versioned provider catalog

Preparatory C03/C13 work owned by Inference. Deliver a bounded native catalog
parser and selection interface for installer configuration. Catalog bytes are
trusted host configuration, never downloaded or supplied by a public operation.
Each entry pins identity, version, acquisition URL, license notice, platform,
minimum OS, runtime policy, recipe, exact size and SHA256. Selection requires an
exact platform and supported runtime policy. No activation follows selection.
Maximum 16 entries and 64KiB input. Unknown fields, duplicate IDs, unsupported
versions, invalid pins and oversized fields refuse the whole catalog. Output is
unchanged on failure. No invented production artifact or Linux engine pin.

Acceptance: valid selection and installer descriptor mapping; malformed/unknown/
duplicate/oversized catalog refusal; platform/runtime mismatch; sanitizer run.
Focused commands: make test-catalog sanitize-catalog. Follow with trusted-file
loading, setup CLI integration and real artifact distribution qualification.
This is preparatory work; no legacy production path is retired yet.

Native catalog_file.c now loads only bounded absolute owner-private single-link
regular files with descriptor/named-inode and nanosecond mutation checks.
Symlink, public-mode, linked, missing and relative inputs refuse. Catalog trust
comes from explicit owner provisioning; this is not a signature verification
or remote catalog update protocol. License is a required bounded notice string;
legal distribution review remains part of the actual package gate.

Setup continuation: add samosa-inference-setup, an optional curl-linked one-shot
adapter with a private host-provisioned catalog and shared installer state root.
Public JSON selects only operation and provider_id; paths, pins, URLs, quotas,
CA/redirect configuration and credential files are host arguments. Catalog list
is model-free/read-only; install/resume/status do not launch engines. Native
host detection supplies architecture and OS version, with no caller override.
macOS minimum_os means product version; Linux minimum_os means kernel version,
with distributions/runtime dependency closure qualified separately. Reject an
unsupported minimum before creating state. SIGINT/SIGTERM propagate cancellation
to acquisition. Use existing installer global lease/quota across all catalog IDs.
Acceptance: production HTTPS fixture install/status/offline retry, certificate
refusal, version/platform/OS/runtime/request/host-config refusal and cancellation;
regular and sanitizer runs on independently copied macOS/native ARM64 Linux.

Focused host/version/catalog qualification now has950 native assertions on both
platforms, regular and ASan/UBSan. Setup CLI has40 checks on both platforms,
regular and sanitized, including actual SIGTERM after one HTTPS body byte,
durable interrupted status, install-without-resume refusal and explicit resume.
Independent full test/sanitize/test-native/sanitize-native/release runs succeed
on macOS and native Debian12 ARM64 (details in the architecture checkpoint).

Explicit optional tests/remote_native.sh additionally serves the previously
pinned macOS static engine over controlled real HTTPS, installs by catalog ID,
retries offline, invokes native executable qualification, then runs the existing
public managed actual-provider acceptance against the downloaded engine and the
read-only pinned model. It observes active generation before cancellation,
requires cancellation and a surviving subsequent answer, then EOF shutdown and
no retained key. This proves actual installed-engine behavior on macOS, not a
production remotely published package catalog, Linux engine or redistribution
license review. No new model copy is made.
